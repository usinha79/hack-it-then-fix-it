# How MCP works and where it can be attacked

> Before you can defend the Model Context Protocol, you have to see it: the three parts, the two ways they talk, and the four lines where trust breaks.

**Module 1 of the MCP Security course.** The map before the territory.

## What this module covers

No attack yet. This module teaches how MCP actually moves: a host, a client, and a server offering tools, resources and prompts, talking either on your own machine or across the web. Every later attack lives on one of four trust boundaries, and most need one dangerous overlap.

## Why it works

An MCP setup is in danger when three things are true at once: the AI can reach private data, it reads content an outsider controls, and it has a way to send data out. Spot that overlap and you have found the attack.

## What you take away

Learn to read the traffic between host and server, find the four trust boundaries in any setup, and watch for the three part overlap. Once you can see them, the rest of the course is watching each attack happen and learning to stop it.
